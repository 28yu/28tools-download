## 2026-07-27 — 議事録の書面デザインを刷新（アイコン廃止・A4 印刷最適化）

**要望**: 書き出された議事録のデザインがいまいち。**アイコンは使わず**、**A4 出力で
バランスよく**収まるようにする。

**対応**:
- **アイコン全廃**: 図解スタイルの Lucide アイコン（`<i data-lucide>`）と、各所の絵文字
  （🗣👤⏰📎✅📋⚠️💬📅📍👥）をすべて削除。`index.html` の Lucide `<script>` も除去、
  `mountMinutes()` の `createIcons()` 呼び出しも削除。
- **クリーンな書面レイアウト**（`render.js`）:
  - ヘッダー＝タイトル＋「日時：/場所：/案件：/出席：」の**ラベル付きメタ**（アイコンなし）＋下罫線。
  - 各セクション＝**色アクセントの縦バー**＋見出し＋件数。決定=緑/ToDo=青/課題=橙/議論=紺/概要=黒。
  - 項目＝**丸番号バッジ**（section 色）＋本文＋「発言：/担当：/期限：/資料：」の控えめメタ。
  - 議論＝左罫線＋トピック＋発言者＋箇条書き。概要は見出し付きセクションに格上げ。
- **A4 印刷最適化**（`minutes.css` の `@media print` ＋ `app.js` の HTML 保存用インライン CSS）:
  - `@page { size:A4; margin:16mm 15mm }`、本文 10.6pt/1.55。
  - `break-inside:avoid`（セクション/項目/トピック）と見出しの `break-after:avoid` で
    ページ途中の分断を防止。`print-color-adjust:exact` で色アクセントを印刷にも反映。
- ラベル用の翻訳キー `txt-speaker`（発言）/`txt-ref`（資料）を i18n.js に追加。

**注意**: `minutesToText()`（コピー用テキスト）は従来通り。マインドマップスタイルはノード図の
性質上そのまま残すが、絵文字ラベルは撤去してテキストのみに。Node でサンプル議事録を
`renderMinutes()` に通し、絵文字/Lucide が出力に含まれないこと・A4 体裁を確認済み。

## 2026-07-27 — UI を「録音中心・停止で自動作成」に再設計（クリック最小化）

**要望**: 打合せ開始時にブラウザを開いて音声入力するのが前提。録音ボタンを目立たせ、
ファイル/資料選択は小さく。停止したら最下部に議事録が自動で出るように。**極力シンプル・少クリック**。

**ユーザーへの確認で決めた仕様**（AskUserQuestion）:
- 「同時に議事録」の粒度＝**録音停止後に自動作成**（録音中は進捗のみ表示）
- 既定＝**高精度版(Gemini)＋キー保存**（初回のみキー入力、以降は録音ボタンだけ）
- **音声も保存**（区間音声を選択フォルダへ）／保存方式＝**フォルダを一度選ぶ方式**
- 録音ボタン＝**先日の全自動モードに一本化**／分割間隔＝**10分固定（詳細で変更可）**
- 補助入力（ファイル/資料/貼付け）＝**「詳細・任意入力」に折りたたむ**／マイク選択・テストは**小さく常時表示**

**新レイアウト**:
1. **録音ヒーロー（最上部・唯一のメイン操作）**: 大きな「🎤 録音を開始」ボタン。押すと録音、
   もう一度で「⏹ 停止して議事録を作成」。停止で自動生成 → **最下部に議事録が出現**。
   下にマイク選択・テスト（小さく常時表示）、初回のみ「API キーが必要」帯、録音中は区間進捗。
2. **詳細・任意入力（`<details>` 折りたたみ・既定は閉）**: 処理方法（簡易版/高精度版）＋API キー、
   分割間隔＋保存先フォルダ、"録音せずファイル・資料から作成"（従来の音声/資料/貼付け＋作成ボタン）。
3. **出力（最下部）**: 議事録プレビュー＋スタイル切替（図解/マインドマップは出力ツールバーへ移動）。

**動作の分岐（録音ボタン1つ）**:
- 高精度版(Gemini): 長時間モード（自動分割・保存・区間ごと Gemini・結合）。停止で最終結合を表示。
- 簡易版(ブラウザ): 通常録音し、**停止時に自動で** Whisper 文字起こし＋分類（フォルダ不要・キー不要）。

**クリック削減の工夫**:
- **API キーを保存**すれば以降は録音ボタンのみ（初回だけ「詳細」でキー入力。未入力で録音を押すと
  自動で「詳細」を開いてキー欄にフォーカス）。
- **保存先フォルダを IndexedDB に記憶**（`saver.js`）。次回以降は**許可の再取得だけ**でフォルダ選択
  ダイアログを省略（`useRememberedWithPermission()`）。「詳細」で事前に選択/変更も可。
- スタイル選択・作成ボタンといった録音前の手順を撤去（生成は停止で自動、スタイルは出力後に切替）。

**変更ファイル**: `index.html`（全面再構成）, `app.js`（`setupRecord`/`startGeminiLongRec`/
`stopGeminiLongRec`/`startSimpleRec`/`stopSimpleRec`/`setRecBtn`/`updateSetupStrip`/`updateFolderStatus`）,
`lib/saver.js`（フォルダ記憶＋許可再取得）, `minutes.css`（ヒーロー・詳細・セットアップ帯）,
`lib/i18n.js`＋`js/main.js`（ja/en/zh 追加）, `main.js?v=` bump。

**メモ / 既知の注意点**:
- 録音中は前回の議事録を隠し（`output-section` を非表示化）、停止後に表示。
- `showDirectoryPicker` 非対応ブラウザ（Safari/Firefox）は**ダウンロード保存に自動フォールバック**
  （フォルダ記憶は使わない）。フォルダ記憶＋許可は Edge/Chrome のみ。
- スモークテスト（Node の簡易 DOM シム）で `init()` が例外なく走ること、初回セットアップ帯の
  出し分け・フォルダ表示・ボタンラベルが正しいことを確認済み。

## 2026-07-27 — 長時間モード（自動分割・保存・全自動作成）を追加

**背景**: 1 時間級の打合せは、1 回の Gemini 生成では出力トークン上限（`maxOutputTokens`）に
達しやすく、`g-err-maxtokens` で「10〜15 分に分割して」と案内していた。手作業での分割は面倒。
そこで**録音を続けたまま一定間隔で自動分割し、各区間を高精度版(Gemini)で自動議事録化して
1 本に結合する**「長時間モード」を実装した。

**動作の流れ**（STEP1 の録音カード内トグル `🕒 長時間モード`）:
1. 録音開始時に**保存先フォルダを一度だけ選択**（File System Access API / `showDirectoryPicker`）。
   非対応ブラウザ（Safari/Firefox 等）は**ダウンロード保存に自動フォールバック**。
2. マイクは録りっぱなしのまま、**既定 10 分（5/10/15 分から選択）ごとに区切り**、
   各セグメントを 16kHz mono WAV で確定。
3. 各セグメントを **①選択フォルダへ保存 → ②Gemini で議事録化**（保存→処理を直列化）。
   セグメントは間隔（分単位）で発生するため、無料枠のレート制限には実質かからない。
4. 完了ごとに**逐次結合してプレビューを更新**。停止時に最終結合＋（必要なら）UI 言語へ翻訳。

**設計上の判断**:
- **保存＝安全網**: Gemini が失敗しても音声はフォルダに残る（`part01.wav`…）ので、
  失敗区間だけ後から手動で再作成できる。保存はブラウザ内で完結（28tools サーバ送信なし）。
- **結合は決定的（AI 追加呼び出しなし）**: `lib/merge.js` が各区間の要約を時間帯付き
  （`【0〜10分】…`）で連結、決定/ToDo/課題は時系列連結、議論トピックは頭に時間帯ラベルを付与。
  追加の Gemini 呼び出しをしないので失敗点を増やさない。
- **全自動なので高精度版＋API キー必須**（簡易版は対象外）。

**追加/変更ファイル**:
| ファイル | 変更 |
|---|---|
| `lib/recorder.js` | `SegmentedMicRecorder` を新設（間隔ごとに MediaRecorder を stop→即再開して単独再生可能な区切りを作る。マイクは解放しない）|
| `lib/saver.js`（新規） | `SegmentSaver`（フォルダ直書き込み or ダウンロードのフォールバック。書き込みは直列化）|
| `lib/merge.js`（新規） | `mergeSegments()` / `segmentLabel()`（区間議事録を 1 本に結合）|
| `app.js` | 長時間モードのオーケストレーション（フォルダ選択→録音→保存→Gemini→逐次結合描画）|
| `index.html` | 録音カード内にトグル・間隔選択・セグメント進捗パネルを追加。`main.js?v=` を bump |
| `lib/i18n.js` | 実行時メッセージ（`lr-*`）を追加 |
| `js/main.js` | 静的 UI ラベル（`aimin-longrec-*`）を追加。`aimin-record-note` を長時間モード対応に更新 |
| `minutes.css` | 長時間モード UI のスタイル |

**既知の注意点 / 落とし穴**:
- `SegmentedMicRecorder` の区切りは古いレコーダーの `onstop` で確定するが、その時点で
  `this.recorder` は**次のセグメントを指している**ため `onstop` 内で `this.recorder=null` に
  してはいけない（次の参照を壊す）。解放は `stop()`/`cancel()` のみが行う。← 実装時に踏んだバグ。
- セグメントの最短間隔は安全上 **30 秒でクランプ**（`Math.max(30000, segmentMs)`）。UI 選択肢は 5/10/15 分。
- 10 分 16kHz mono WAV は約 19MB → gemini.js が自動で Files API 経由になる（インライン上限 15MB 超）。
- `showDirectoryPicker` は**クリック直後のユーザー操作**でのみ呼べるため、録音開始前に先に呼ぶ。
  マイク許可(getUserMedia)より前に実行してジェスチャを消費しないようにしている。

## 実装履歴 (時系列)

1. **初版**: 2 層構成 (Gemini / Whisper簡易版)、図解＋手描き風スタイル、サイト統合
   (サイドバー3箇所・翻訳・OGP/GA/AdSense)。`renderMinutes` の構造化スキーマを確定。
2. **パスワードロック**: 限定公開化。`data-locked` リンク委譲 + ページガード + sitemap 除外。
3. **多言語化(UI)**: 静的は `data-lang-key`+`translations.aiMinutesPage`、動的は `lib/i18n.js`。
   `changeLanguage()` が `28tools-langchange` を dispatch → app.js が購読し再描画。
4. **容量制限の撤廃**: インライン ~20MB を超える場合は **Gemini Files API**(resumable upload)へ
   自動切替。最大 2GB・48h 保持。`INLINE_LIMIT_BYTES=15MB` 境界。
5. **マイク録音(案A)**: `recorder.js`。getUserMedia + MediaRecorder → 停止時に
   16kHz mono WAV へ変換。**端末ストレージには保存しない**（メモリ Blob のみ）。
6. **マイクテスト + デバイス選択**: AnalyserNode によるレベルメーター、enumerateDevices で
   入力デバイス選択、devicechange で自動更新。
7. **MAX_TOKENS 対策**: thinking 無効化、`maxOutputTokens=65536`、プロンプトで厳格な
   出力上限(要約厳守・逐語禁止)、temperature 0.2、`parseJsonLoose`+`repairTruncatedJson`で
   途中切れ JSON を復元。修復不能かつ MAX_TOKENS は「音声分割」を案内。
8. **Whisper CDN フォールバック**: jsdelivr → esm.sh → unpkg を順に試行。
9. **マインドマップ**: 手描き風(Rough.js)を撤去し、マインドマップ(SVG, foreignObject)に置換。
10. **文言整理**: 「イラスト」表記を全削除、見出しを「AI議事録 自動作成」、説明から「建築現場の」削除。
11. **議事録本文の翻訳**: 言語切替時に `translateMinutes()` で本文も翻訳（構造保持）。
    結果は `state.translatedByLang` にキャッシュ。表示/コピー/HTML保存は `currentData()` で追従。
12. **デザイン改善**: 会議ヘッダー/概要/セクション見出し/カードを色分け・アクセント化。
13. **503 リトライ + 翻訳バグ修正**: 503/500 をバックオフ自動リトライ。翻訳キャッシュは
    `detectContentLang()`(かな→ja/漢字→zh/他→en) で**中身の言語**をキーにする（UI言語と混同しない）。

## 重要な判断・知見

- **Gemini を主経路に**: ネイティブにマルチモーダル＋音声直接入力＋無料枠＋CORSでサーバ不要。
  「不特定多数 × 無料 × マルチモーダル」を、ユーザー自身の無料キーで成立させる。
- **2.5-flash の MAX_TOKENS**: 思考トークン消費＋長尺音声で JSON が途中で切れる。
  thinking 無効化＋出力上限＋出力量制限＋途中切れ修復の多段で対処。
- **録音は端末非保存**: メモリ内 Blob のみ。停止時にマイク解放。高精度版のみ Google へ送信。
- **本文翻訳の言語キー**: 中身の言語は UI 言語と一致しない。必ず内容から判定すること
  (ここを取り違えると「翻訳済み」と誤判定して訳さないバグになる)。
- **CACHE_NAME 的なものは無い**: このツールは Cache API を使っていない (pdf-to-excel とは別)。

## 既知の制約・未対応

- **簡易版(Whisper)は業務ネットワークで不安定**: 外部 CDN/HuggingFace から ~150MB の
  モデル DL が必要。社内ネットワークでブロックされると失敗(CDN フォールバックでも回避不可)。
  → 確実にしたい場合はモデルを 28tools 自サイト配信にする案あり(未実装)。
- **超長尺音声**: 65536 トークンでも切れる場合あり。根本対策は「音声分割」または
  「①文字起こし→②要約」の 2 段階処理(未実装)。
- **資料の寸法・記号の精密転記は保証外**(マルチモーダルでも誤読あり)。
- **話者識別はベストエフォート**(厳密なダイアライゼーションはしていない)。
- **翻訳は切替ごとに未訳言語で 1 回 Gemini を呼ぶ**(キャッシュ後は消費なし)。
  自動翻訳ではなく明示ボタン式にする案も保留中(ユーザー判断待ち)。
- **専用アイコン未作成**: サイドバー/カードは暫定で `icon-AI.png` を ai-news と共用。
