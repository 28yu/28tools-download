# セキュリティ設定（Supabase）の手順

解析画面（`analytics/dashboard.html`）をログイン制にし、不審なアクセスを記録する表を作る。
Supabase の画面で行う作業は **1 回だけ**。所要 10 分ほど。

> このフォルダは公開リポジトリにあるので、**メールアドレスやパスワードを書いてコミットしないこと**。

## 手順

### ステップ1: 表と関数を作る
1. https://supabase.com/dashboard → 28tools のプロジェクト → 左メニュー **SQL Editor**
2. `1-setup.sql` の中身を全部貼り付けて **Run**
   （何度実行しても安全。この時点では解析画面は今までどおり見られる）

### ステップ2: 自分のログイン用アカウントを作る
1. 左メニュー **Authentication** → **Users** → **Add user** → **Create new user**
2. 自分のメールアドレスと、**長くて推測されにくいパスワード**を入れる
   （パスワード管理アプリで生成したものがおすすめ）。**Auto Confirm User** にチェック → 作成
3. **Authentication** → **Sign In / Providers**（または Settings）で
   **「Allow new users to sign up」をオフ**にする（知らない人がアカウントを作れないように）
4. SQL Editor に `2-add-admin.sql` を貼り付け、`ここに自分のメールアドレス` を書き換えて **Run**
   → 下に自分のメールアドレスが 1 行出れば成功

### ステップ3: ログインを確認してから「誰でも読める」を閉じる
1. https://28tools.com/analytics/dashboard.html を開く → 右上「🔒 ログイン」→ ステップ2のアカウントで入る
2. データが表示されたら、SQL Editor で `3-close-public-read.sql` を **Run**
3. 解析画面を再読み込みして、上のオレンジ色の警告が消えていれば完了

## 何が記録されるか（解析画面の「🛡 セキュリティ」タブ）

| 種類 | 意味 | 記録する場所 |
|---|---|---|
| 許可外のプログラム | 予定にない場所からプログラムが読み込まれた（改ざんの兆候。閲覧者のブラウザ拡張機能のこともある） | `js/main.js`「セキュリティ監視」 |
| 読み込みブロック | ページの CSP（禁止ルール）で止めた読み込み・送信 | `js/main.js` |
| 攻撃の下見 | `/wp-admin` `/.env` など攻撃で狙われる場所へのアクセス | `404.html` |
| 存在しないページ | リンク切れなど | `404.html` |
| ログイン成功／失敗 | 解析画面のログイン | `analytics/dashboard.html` |

- IP アドレスは末尾を伏せて保存（プライバシーポリシーにも記載済み）。180 日で自動削除
- 同じ内容は 1 時間ごとに 1 行へまとめる。全体で 10 分 300 件まで（大量送信で表が膨らまない）
- 記録の書き込みは関数 `log_security_event` 経由だけ。表を直接読み書きできるのは管理者（読み取りのみ）

## 困ったとき

- **ログインできない**: Authentication → Users でパスワードを再設定（「Send password recovery」か、ユーザーを作り直して `2-add-admin.sql` を再実行）
- **急いでデータを見たいのにログインできない**: `3-close-public-read.sql` の末尾にある「元に戻したいとき」の 3 行を実行すると、一時的に以前の状態に戻る（見終わったら同じファイルを再実行して閉じる）
